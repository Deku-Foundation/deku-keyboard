# FlorisBoard open bug reports — Deku triage audit

**Source:** [FlorisBoard open issues tagged `bug`](https://github.com/florisboard/florisboard/issues?q=is%3Aissue+state%3Aopen+label%3Abug)  
**Captured:** 2026-10-26  
**Inventory:** 92 open upstream reports returned by GitHub search.  
**Important:** These reports target upstream FlorisBoard and often mention old app versions, ROMs, hardware or third-party apps. An issue being open upstream does **not** prove that the same defect exists in Deku Keyboard. This is a preliminary title/body triage, not a claim that the reports were reproduced or root-caused.

## Triage rules

- **P1 — high impact:** potential crash/freeze, data/config loss, failure to type, or corrupted input. Reproduce first and inspect state transitions/logs.
- **P2 — functional correctness:** text editing, IME/editor integration, language composition, clipboard behavior, and input-device compatibility.
- **P3 — usability/presentation:** labels, spacing, tooltips, themes, and lower-risk UI behavior.
- **Scope:** check whether the report is actually a defect or a feature request rather than assuming every report marked `bug` is a regression.

## Required engineering process

For every fix: (1) verify current Deku code and upstream issue history, (2) reproduce on the current branch or document why reproduction is unavailable, (3) identify the responsible layer, (4) add a minimal regression test or document the testing limitation, (5) make the narrowest safe change, (6) run targeted tests and `./gradlew clean assembleDebug`, and (7) manually verify IME/editor/device-specific issues on an actual device before calling them fixed.

Do not close issues in the upstream FlorisBoard repository from this independent fork. Track Deku remediation in its own commits/issues and retain upstream copyright and license attribution.

## Source-review findings

- **[#3300 — Potentially time-consuming operations on the UI thread](https://github.com/florisboard/florisboard/issues/3300):** the inherited `DekuApplication` called `cacheDir.deleteContentsRecursively()` synchronously in both normal initialization and the locked-user path. Removed the unconditional recursive purge from Application startup because Android's cache directory is disposable and broad cleanup here adds main-thread disk I/O. This is a targeted performance correction, not proof that all startup work is now off the main thread; CI build validation is still required.
- **IME root lifecycle hardening (related reports not yet root-caused):** `DekuImeService.onCreateInputView()` now removes existing direct-child `ImeRootView` instances before attaching a new Compose root, and removes the tracked root in `onDestroy()`. This prevents duplicate custom root views on repeated input-view creation; it is not claimed as a confirmed fix for any specific upstream report until reproduced.

## Source-review findings

- **[#3294 — Android inline-suggestion inflation crash](https://github.com/florisboard/florisboard/issues/3294):** current code passed a mutable chip height directly to `InlineSuggestion.inflate`. The `dev` patch now accepts a positive height only when it is inside the provider's `InlinePresentationSpec` bounds, otherwise requests `WRAP_CONTENT`. It also catches documented invalid-state/argument failures per suggestion so one bad provider item does not cancel the whole inflation loop, and adds unit tests for unset, negative and out-of-range heights. Status: **patch committed; waiting for CI and Android 16/device verification**.

## Source-review findings

- **[#3335 — Large selection truncated by Smartbar Copy](https://github.com/florisboard/florisboard/issues/3335):** the Smartbar Copy and Cut paths used `state.content.surroundingText.textSelected`, a cached selection snapshot. The current `dev` patch reads the selection directly from the active `InputConnection` at action time, preserving the internal-only clipboard path and avoiding fallback to stale cached text. A focused JVM test covers a 128 KiB selection returned by the live connection. Status: **patch committed; waiting for CI and manual reproduction in Joplin/Obsidian or equivalent editors**.

## Completion criteria

A report can be marked **fixed in Deku** only when there is a linked Deku commit/PR, regression-test evidence (or a documented reason why the path cannot be unit-tested), green CI, and manual device/app validation for behavior depending on Android IME lifecycle, ROMs, stylus/hardware keyboards or third-party editors.
